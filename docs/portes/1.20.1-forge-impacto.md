## 2. Resumo

**Tamanho: grande.** Mudam o loader (NeoForge → Forge) e a versão do jogo para antes dos componentes de item e
dos payloads. O código comum quase todo é tocado ao menos nos imports (`net.neoforged` em 112 de 232 arquivos),
mas a maior parte é mecânica. A lógica pura com JUnit não muda (nenhuma classe pura usa recurso do Java 21 ou
API do jogo). Modelos, blockstates e texturas também não: a transformação raiz que gira o roteador existe no
Forge 1.20.1 (C, SRC `ExtendedBlockModelDeserializer` lê `"transform"`; `TransformationHelper` aceita
`"origin": "center"`).

**As três maiores mudanças:**
1. **Rede (≈60 arquivos):** `CustomPacketPayload`/`StreamCodec` não existem; volta o `SimpleChannel`. Estratégia:
   uma camada própria com os mesmos nomes (`StreamCodec`, `ByteBufCodecs`, `CustomPacketPayload`) sobre
   `FriendlyByteBuf`, para cada payload mudar só os imports.
2. **Capabilities e o cache (≈20 arquivos + os blocos de teste):** sem `BlockCapabilityCache`; `LazyOptional` e um
   cache próprio por vizinho, invalidado pelo `addListener` do `LazyOptional` e pelo `neighborChanged`. É a parte
   mais delicada para a performance.
3. **Mekanism dividido em quatro químicos:** gás, infusão, pigmento e slurry, cada um com handler e capability
   próprios; e o Ars 1.20.1 sem capability de Source.

**Fica de fora ou perde algo:**
- JEI: Shift + clique de um ingrediente do JEI para a tela de filtro (`IGhostIngredientHandler` não tem `quickMove`
  na 15.20; C, JAR). Arrastar continua.
- Mundos e itens do `main` não abrem no ramo (seção 6).
- Mekanism: decidir entre só gás ou os quatro subtipos (seção 4).

## 4. Mods opcionais

**Mekanism 10.4.16 (alto).** Quatro tipos: `IGasHandler`, `IInfusionHandler`, `IPigmentHandler`, `ISlurryHandler`,
todos `IChemicalHandler<C, S>` com quantidades `long` e `Action` igual ao do `main`. Métodos com nomes diferentes
(`getTanks`, `getTankCapacity`). As capabilities ficam em `mekanism.common` (fora da API), mas são criadas por
`CapabilityManager.get(CapabilityToken)`, então o compat obtém a mesma instância sem depender de `mekanism.common`.
Registros separados (`MekanismAPI.gasRegistry()` etc.); fora `empty`, os ids não se repetem entre os quatro (P).
No JEI são quatro tipos de ingrediente. C (JAR).
- **(a) só gás:** quase o código de hoje; deixa slurries (processamento de minério) sem transporte.
- **(b) os quatro:** `ChemicalTransfer` genérico em `<C, S>`, uma passada por subtipo na face; a chave do filtro e do
  Tanque Químico guarda o subtipo. Cerca de três vezes o trabalho.
- **Sugestão:** escrever o código já genérico e ligar os quatro; se o prazo apertar, entregar só o gás primeiro.

**Ars Nouveau 4.12.7 (médio).** Não há `ISourceCap` nem capability de Source; só `ISourceTile` (`int`, sem simulação:
`getSource`, `getMaxSource`, `addSource`, `removeSource`, `canAcceptSource`). `SourceManager.addInterface` e o
`ISpecialSourceProvider` existem; `SourceUtil.takeSourceMultiple` não. C (JAR).
- O `ScalarAccess` da Source passa a ser `instanceof ISourceTile` no BE vizinho, com a simulação feita por conta;
  o Tanque de Source implementa `ISourceTile` e continua como provider no `SourceManager`.
- V: se os Relays do Ars 1.20.1 aceitam um `ISourceTile` que não estende `AbstractSourceMachine`.

**JEI 15.20 (baixo a médio).** `IIngredientSubtypeInterpreter` no lugar de `ISubtypeInterpreter`; o ingrediente
clicável é implementado pelo mod (`IClickableIngredient`); `RecipeTypes.CRAFTING` recebe a receita direto (sem
`RecipeHolder`); sem `quickMove` no ghost handler. C (JAR).

**GuideME 20.1.14 (baixo).** Guia declarado só por arquivo (`guideme_guides`), os mesmos tags MDX. O livro guarda
o id no NBT (`guideId`), não num componente: muda só o `GuideBook`. C (JAR); comportamento das páginas P.

**Allthemodium 2.5.7 / All The Tweaks 2.4.2 (baixo).** Tags em `forge:` (`forge:ingots/allthemodium`,
`forge:storage_blocks/...`), todas as usadas pelas receitas existem; `allthetweaks:atm_star_shard` existe. C (JAR).

**Logistics Network 1.3.0 (baixo, só o benchmark).** As classes têm os mesmos nomes, mas faltam
`loadNodeState`/`saveNodeState`, `NodeClipboardConfig.joinNetwork` e `Config.asyncPlanning`; existem setters por
canal (`ChannelData`). O adaptador do benchmark precisa de outra implementação. C (JAR). Os tetos padrão do
`LnChannelPlan` nessa versão: V.

## 5. Performance

- **Sem tick por bloco:** igual; o `NetworkManager` roda no `TickEvent.ServerTickEvent` (fase `END`). C.
- **Capability só por cache:** não há `BlockCapabilityCache`. O `CapCache` próprio guarda o `LazyOptional`
  resolvido e só volta ao `getCapability` quando o listener do `LazyOptional` dispara, quando o BE do vizinho muda
  ou no `neighborChanged` do roteador. O custo no laço quente fica o mesmo de hoje (um campo lido). Um GameTest
  deve provar que o cache acorda ao trocar a máquina vizinha. Risco alto, porque um erro aqui deixa a rede presa
  a um handler morto.
- **Nada de sincronizar com a tela fechada:** igual; só muda o transporte (`PacketDistributor.PLAYER`). C.
- O Ars sem simulação atômica: o valor pode mudar entre simular e executar, o que é aceitável com o tick único.

## 6. Dados do mundo

Um mundo do `main` (1.21.1) não abre no 1.20.1: o Minecraft não faz downgrade de mundo. Itens do mod em mundos
1.20.1 guardam o estado em NBT, não em componentes, então também não há caminho de volta. O changelog do ramo deve
dizer que ele é para mundos novos ou para packs 1.20.1 (ATM9).

## 7. Plano em tarefas

Ramo `mc/1.20.1-forge` a partir do `main`, nunca de volta. Cada tarefa termina testável.

1. **Build:** `legacyforge`, Java 17, `mods.toml`, Parchment, versões das dependências do pack; uma run de teste
   que carrega o Mekanism remapeado (prova o maior risco do build). Pronto: `./gradlew build` só com a lógica pura
   e o JUnit passando.
2. **Registros, config, eventos, Java 17:** a classe `@Mod`, registros, `ForgeConfigSpec`, ticks, os `switch` por
   padrão. Pronto: o jogo abre com os blocos e itens.
3. **Dados:** pastas no plural, condições `forge:`, tags `forge:`, receitas, loot, `empty.nbt` regerado. Pronto:
   receitas no JEI do runClient.
4. **NBT no lugar dos componentes:** a fachada `ModDataComponents`, block entities, SavedData. Pronto: o roteador
   guarda e recarrega a configuração.
5. **Rede:** a camada `StreamCodec`/`ByteBufCodecs` própria e o `SimpleChannel`. Pronto: todas as telas abrem e
   os testes de ida e volta dos payloads passam.
6. **Capabilities, cache e motor:** `CapCache`, Bulk, armazenamentos, transferência de itens, fluidos e energia.
   Pronto: os GameTests da run comum passam (com os blocos de teste ganhando BE).
7. **Telas e render:** assinaturas, vértices, visor 3D, roda, área. Pronto: as capturas do `WA_SCREENSHOT`.
8. **Mekanism** (decisão da seção 4) e a run de GameTests de químicos.
9. **Ars Nouveau** e a run de Source.
10. **JEI, GuideME, Allthemodium** e a run do ATM.
11. **e2e, guia, benchmark** (adaptador do Logistics Network 1.20.1).
12. **Release do ramo:** `wirelessautomate-<versão>+mc1.20.1-forge.jar`, tag `v<versão>+mc1.20.1-forge`.
